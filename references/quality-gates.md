# 验收与交付

## 制作前：页数、语言、生图路径、文案与结构

- 用户已明确总页数及文案语言，`page_count_confirmed=true`、`language_confirmed=true`；全部逐页上屏文案已展示并取得明确确认，`copy_status=approved` 且保留实际确认记录。未确认时不生成正式页面或制作PPT，启动时的单张能力诊断图除外。
- 需要生图时有本任务实际诊断图及参考输入测试记录，未把聊天可用、配置存在、旧记录或dry-run当作通过。失败时已展示API配置/跳过选项，选择API时通过本机隐藏输入、实际验证并完成全局保存；项目与日志不含Key。选择跳过时保留明确选择及效果提示，标记 `direct-editable`。只重建现有定稿图时记录 `not-required`，不要求API配置。
- `slide_count` 与逐页文案数量一致。项目报告第1页封面、第2页目录、最后1页结尾，计入总页数；目录名称与正文分组一致，结尾有实际结束语。
- 封面、目录、结尾已绑定同家族原页A01/A02/A19或B01/B02/B28；执行生图时分别实际提交对应原图，直接制作时实际查看对应原图并迁移版式，不虚构生图记录。

## 阶段一：图片验收

先把生成页与对应原始参考页并排比较。按以下六项逐条给出 `match / revise / not-applicable` 和短理由，保存到生成日志，不能只凭整体好看判断：配色分工、标题与页眉、主体布局、流程关系、分点层级、信息密度与证据比例。流程/分点明显偏离时必须修正，不能因为颜色相似就放行。没有实际生成样页时，不宣称视觉效果已验证。

- 总页数与已确认内容计划一致，包括目录及所有封面、结束页；文件从 `S01.png` 连续到最后一页。
- 每张图片16:9且分辨率足以投影；裁切未损伤标题、图注、坐标轴和证据。
- 逐页比对 `text_exact`，核对已确认语言，检查中文字符或英文拼写/大小写、专有名词、公式、上下标、数字、小数点和单位；英文稿无无意残留的中文模板。
- 真实图片未被模型重画成伪证据；结果图所有值均有真实来源。
- 开题中未完成部分保持计划语气，预实验、预期指标和最终结果明确区分。
- 蓝白主调、标题基线、字体层级和红色语义一致；方法与实验页在正常投影尺度可读。
- 总览图中的页顺序正确，已修订页的缩略图同步更新。
- 项目报告首尾与所选原页家族的构图、蓝白分区、字重层级一致，目录保持对应横行结构，三类页面没有被普通内容页替代。
- 按下述逐页检查清单修复图片遮挡与流程关系，修复通过后才进入重建；原图中存在的问题不照搬到PPT。

## 阶段二：可编辑验收

- 页面比例、数量和顺序一致，未用一张整图替代主要内容。
- 可见标题与正文为非隐藏原生文本；表格为单元格对象，数据图表包含可修改的数据。
- 流程图节点、标签和线条可单独选择，语义关系准确；分组不妨碍编辑。
- 公式编辑类型有证据：原生公式、数学文本或图片，不能混称。
- 真实照片、界面截图等保留图片形式时，交付说明准确区分“可替换图片”和“内部可编辑”。
- 没有透明文字层冒充正文，没有把数据图或表格变成SVG图片冒充原生对象。
- 字体替换与换行已经检查；标题和正文不溢出、不被证据图覆盖；引用没有丢失。
- 有阶段一图片时逐页比较重建渲染与图片；`direct-editable` 比较真实A/B参考及风格锁，检查同样的可读性与关系。视觉差异合理，事实修正以源材料为准。

## 逐页重叠与流程连接检查：发现即修复

所有页均检查全尺寸局部及正常投影尺度，联系表仅用于顺序与一致性检查。先用边界框、溢出检测等能力定位可疑区域，再以实际渲染确认，不能只看对象计数或自动检测“通过”。

| 类别 | 必查内容 | 典型修复 |
|---|---|---|
| 字与字 | 标题/正文/图注是否互压，字重叠、行重叠、断行、文本框裁切，字号替换后是否越界 | 调整框宽高、行距、内边距与分栏；保留已确认语义，避免靠过小字体硬塞 |
| 字与图 | 图是否盖住标签或正文，文字是否遮住曲线、坐标、数值、截图关键区域 | 重新留出标注区、调整图幅与文本位置、修正图层顺序 |
| 图与图/组件 | 证据图互盖、表格压线、模块越界、框与节点错位、裁切损伤，装饰是否挡住内容 | 调整大小、间距、裁切和层级，保持证据比例 |
| 流程节点 | 节点齐全、标签与所属节点对应、容器包含关系正确 | 对照节点清单补全、移动/放大节点，清理重名与重复组件 |
| 箭头与连接 | 每条边起终点、方向、箭头头型、分支标签、反馈回路均与边列表一致 | 重新绑定正确节点锚点或重算独立线端点，改折线路由与图层 |

节点内文字、框内图、背景容器等是有意包含，不能机械视为非法重叠；判定重点是是否遮挡、误导或破坏可读性。标签不得压在线上或被连接线穿字。

逐条对照边列表的 `from_node`、`to_node`、`from_side`、`to_side` 检查：线从正确源节点边界发出，箭头到达对应目标边界且箭头头部可见；不能悬空、穿入目标中央、接错邻近节点、反向，或在绕行中误连第三个模块。检查线是否被图片/形状盖住，分叉处是否清晰，交叉是否产生错误关系。语义为包含/并列的模块不强加顺序箭头。

优先用锚定节点的原生连接线；工具支持时试移一个代表节点，检查连线跟随，再恢复最终位置并渲染。独立线需重算端点并说明移动节点须同步调整。

保存页码、问题、修复和复查结果到 `.build/layout-qa.json` 等内部文件。执行“渲染 → 检查 → 修复 → 重新渲染 → 复查”直到已发现问题解决；修改母版/公共布局时检查全部受影响页，更新最终预览与总览。不得只输出问题清单而不修正，也不得用旧预览证明新版本通过。工具限制确实无法修复时，标明具体页、影响与未完成状态，不能声称全部检查通过。

## 辅助检查脚本

使用当前可用、装有Pillow的Python环境；不要为此改动系统Python或自动安装包。

```bash
python scripts/audit_outputs.py --images /absolute/project/images --plan /absolute/project/content-plan.json --report /absolute/project/.build/image-audit.json
python scripts/audit_outputs.py --pptx /absolute/project/output/defense.pptx --plan /absolute/project/content-plan.json --report /absolute/project/.build/pptx-audit.json
```

也可同时提供 `--images` 与 `--pptx`。脚本检查PNG命名、尺寸、总页数、16:9、原生文本/表格/图表计数、命名流程节点、OMML公式、嵌入图表数据源以及可能铺满页面的图片。`expected_objects` 为最低预期数量。

脚本输出 `issues` 为需修复项、`warnings` 为需人工复核项。全页背景纹理可能触发警告，需确认背景不承载主要文本和数据。脚本无法可靠判定遮挡、文字透明度的所有继承情况、分组中的图像覆盖率、公式正确性或PowerPoint实际编辑体验，不能作为自动“完全可编辑”认证。

`expected_objects.formula` 只检查原生OMML数学公式的最低数量；若选择普通可编辑数学文本，按 `text` 计数，并在元素清单中标为数学文本，不能用该计数声称原生公式能力。

## 交付范围

`image-only`：全尺寸PNG套件、总览图、内容计划、风格锁和逐页提示词。图片ZIP是便于下载的包装，不代替逐页原图。

`rebuild-only`：最终可编辑PPT/活跃呈现文稿，必要的素材与数据、元素清单和可运行的创作源码。原始输入图保留，若不需要重复交付不重复打包。

`two-stage`：上述两类成果。需要文件时导出 `.pptx`；若当前工具默认活跃会话，遵循用户明确的文件要求，同时保留可用会话成果。

`direct-editable`：可编辑PPT、渲染预览、内容计划、风格锁、元素布局清单、必要素材数据及创作源码。明确本次按用户选择跳过Image 2，效果和参考还原度可能下降；不交付虚假的Image 2套件、不把PPT渲染图标成生图结果。诊断图不计入正式套件或页数。全局凭据与Key都不打包进项目。

用户已指定页数时不能在交付时自行加入验收页或额外说明页。最终消息指出仍为图片的科研素材和任何受限的公式/图表页，不给整个文件笼统的“100%可编辑”标签。
