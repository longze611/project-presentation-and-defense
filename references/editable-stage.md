# 阶段二：从定稿图片到可编辑PPT

## 重建原则

用户按启动流程明确选择 `direct-editable` 时，直接由真实A/B参考、已确认语言的文案和风格锁建立原生对象布局，跳过图片拆解。仍使用本文件的对象映射与质量检查；无生成图时不伪造图片来源或像素比较记录。

图像模型不会可靠提供真实图层，也不能从一张图片恢复原始矢量、数据和被遮挡内容。这里的“拆解”是根据可见几何、内容真源和素材逐个重建，不是宣称已经取回隐藏的源文件。

先读取当前环境的Presentations技能及其实现和可编辑证据文档。用户要求的可编辑流程图、表格与数据图应使用原生对象。学术流程图中的矩形、节点、连线是必要语义结构；装饰插画仍使用真实或生成的图片，不靠大量形状硬拼。

## 元素映射

| 图片中可见元素 | PPT重建方式 | 可编辑边界 |
|---|---|---|
| 标题、段落、图注、参考文献 | 原生文本框/段落/富文本run | 可改字、字体、颜色、对齐 |
| 蓝色标题条、边线、浅底分区 | 原生形状或母版元素 | 可改颜色、位置、大小 |
| 表格 | 原生表格及单元格 | 可增删行列、改值、改格式 |
| 柱图、折线、散点等 | 原生数据图表，保留数据系列与数据工作簿 | 可改数据、轴、图例和系列 |
| 技术路线、系统框架、状态图 | 原生节点、标签、连接线，按模块分组 | 节点、文字、连接可修改 |
| 简单公式 | 原生公式或可编辑数学文本 | 必须说明编辑类型 |
| 复杂公式 | 支持时用OMML/原生公式；否则保留LaTeX源并披露限制 | PNG/SVG公式不属于原生公式可编辑 |
| 甘特图/进度安排 | 原生表格，或任务条与时间轴形状 | 可改任务、日期、持续区间 |
| 照片、显微图、扫描件、真实界面 | 原始图片或准确局部裁切 | 可替换、裁切、移动，内部像素不可编辑 |
| 复杂装置/材料3D插画 | 图片，叠加独立原生标签 | 插画内部不可编辑，标签可改 |
| 背景纹理 | 纯色/原生渐变优先，必要时独立背景图 | 允许图像装饰，不能含主要正文和数据 |

原生SVG可缩放，但普通SVG插入不等于标签、数据点和公式可编辑。不要把形状集合中的每个文字转成路径。

## 分析与element-map.json

先识别大区块，再细分文字和证据图。对于每页：

1. 核对图片尺寸与总页数，读取风格锁和该页内容计划。
2. 区分版式固定元素与正文元素，抽取标题基线、分栏边界、图像裁切范围。
3. 每个元素写入来源、文字、几何、图层和重建类型。
4. 流程图另写节点与边，每条边包含唯一ID、`from_node`、`to_node`、`from_side`、`to_side`、方向/箭头头型、线型和语义标签；有转折时记录路由点。含义不明先回源核实，不能仅凭线条靠近哪个节点推断关系。
5. 表格回源逐单元格录入；图表从原数据重建，图像识别仅辅助。没有数据时不可用目测值冒充精确结果。
6. 对被遮挡、模糊和无法识别内容写入待核实项，回到用户材料查证；不要补写“看起来合理”的文字。

坐标使用归一化 `[x,y,w,h]`，每个值在0—1内，原点为左上。重建时 `left=x×W`、`top=y×H`、`width=w×W`、`height=h×H`。像素来源为 `[x_px/W_img, y_px/H_img, w_px/W_img, h_px/H_img]`。裁切边界同样记录归一化值，不盲目复用另一分辨率的像素值。

```json
{
  "canvas": {"width": 1280, "height": 720},
  "slides": [{
    "id": "S09",
    "reference_image": "images/S09.png",
    "elements": [{
      "id": "S09-title",
      "type": "text",
      "bbox": [0.0375, 0.0389, 0.925, 0.0806],
      "z": 20,
      "text": "从content-plan读取的准确标题",
      "font_size_pt": 30,
      "color": "#0B4FA1",
      "rebuild_as": "native_text",
      "content_source": "content-plan.json#S09",
      "editable": true
    }],
    "nodes": [],
    "edges": [],
    "differences": [],
    "unresolved": []
  }]
}
```

图表元素另外记录 `data_source`、`chart_type`、`categories`、`series`、`axis_units`、`axis_range`、`error_bars`；真实图片记录 `asset_path`、`crop`、`alt`、`citation`。不为照片虚构“可编辑内部元素”。

## 内容真源与图片冲突

文字、数值、公式和引用冲突时以经核实的源材料为准，修复图片或在差异记录中说明。不能在图像中发现伪公式后原样重建。没有内容计划而只有图片时，先转录，再核对专业术语、数值和公式；关键不确定项须获得材料佐证。

没有原始数据的文献原图可以作为真实引用图保留并说明编辑边界；若用户要求其数据图也原生可编辑，需要取得数据或将读图估值明确标为近似，并在适合的场景中得到用户同意。数据未知时先完成其他页，不生成假的原生数值图。

## 对象创建顺序

1. 创建16:9画布、主题字体和母版，重建白底、页眉、蓝色细线、页码。
2. 添加主要证据区布局，保持原图的图文占比。浅蓝底和边框保持独立对象，不能把正文烧进背景。
3. 使用原生文本框排入核实文本，合理拆分强调run；每行每字一个文本框会妨碍后续编辑，应按标题、段落、标签等语义分组。
4. 重建表格和数据图，随后重建流程节点与连接线，最后添加真实图像及其可编辑标注。
5. 公式按照真实支持能力创建。不能导出原生数学公式时，不声称公式已完全可编辑；在源文件保留LaTeX，继续完成其他可编辑元素，并说明具体受限页。
6. 添加来源及讲稿备注。内部制作记录放项目QA文件，不写入面向观众的页面或备注。

命名建议：`S09-title`、`S09-body-01`、`diagram-S09-node-01`、`S09-edge-01`、`S13-chart-01`、`S13-table-01`。命名服务定位，不代替真实对象类型验证。

层级由低到高为：背景0、分区10、图像和数据证据20、正文30、关键标注40、页眉页脚50。绘图顺序实际以工具模型为准，需渲染确认。

## 连接关系与编辑体验

优先使用锚定节点的原生连接线，移动节点后连线能跟随。工具无法锚定时使用独立线并保留边列表，说明移动节点需同步调整连线。按研究模块建立组，用户应能选中单个节点并更改标签。

创建后逐条对照边列表检查最终渲染：起点贴合指定源节点边界，箭头抵达正确目标的指定边界，方向、分支标签和反馈路径正确，线与箭头头部均可见；不能有悬空端点、接错模块、穿字或被图片覆盖。工具支持时试移一个代表节点确认锚定，再恢复最终位置。节点位置/大小改变后重新检查所有相关边，独立线须重算端点。

节点标签与节点底色可以是同一含文字的形状，不要求强拆两层。反馈线不能和主线混在一起造成错误因果。真实流程关系比像素位置更重要。

图表必须设置轴标题、单位、类别、图例、数值格式和必要的数据范围；原生图表若只有缓存值而没有可编辑数据源，需要确认PowerPoint能实际修改数据。表格不能靠几十个无关联文字框和线条假装原生表格。

## 可视与结构双重验证

先完成一张方法图页和一张含表格/图表的证据页，渲染并对照图片，验证接口、字体和可编辑性，再扩展全套。这是本地验证，不意味着必须等待用户逐页确认。

逐页按同尺寸比较：标题位置、字号层级、分栏比例、颜色、图表和引用。可叠加或做差异图定位边界偏移，但抗锯齿和字体替代会产生差异，不能用单一像素相似度决定学术正确性。

全套完成后按 [验收清单](quality-gates.md) 逐页检查字与字、字与图、图与图的意外重叠、裁切及流程箭头端点；修改源对象并重新渲染，复查受影响区域及相关连线后再交付。生成图片是视觉蓝图，其中的遮挡或错误关系必须修复，不能按像素照抄。母版修改后重查全部受影响页面。

导出后用Presentations的检查能力及OOXML结构检查确认真实文本、原生表格、原生图表和公式类型。静态结构不能证明对象未隐藏、文字未被覆盖、连线能跟随或PPT数据编辑菜单可用，仍需实际渲染与必要的界面检查。

“一页一图+透明OCR”是无效结果。即使文件中有大量文本形状，也要检查主要可见内容是否仍依赖整页截图。
