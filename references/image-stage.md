# 阶段一：Image 2.0整页图像

## 开始条件

总页数、文案语言及全部逐页文案须已由用户明确确认，`content-plan.json` 的 `copy_status` 为 `approved`，并完成本次 [启动测试](preflight-and-credentials.md)。未确认时只整理材料与文案，不生成正式页面；启动时的一张诊断图是例外。用户明确选择 `direct-editable` 时不执行本阶段。后续提示词使用已确认语言的 `text_exact`、图表标签与节点关系，不能自行改写论点或增减页数。

## 工具与模型

先读取当前环境的 `imagegen` 技能，采用其内置图像生成路径。用户说“image2.0”不等于授权付费API、切换账户或要求用户提供密钥。

若内置工具无法指定后端，只报告可验证的工具信息，`model` 写 `unexposed`；若任务必须严格使用可证明的 `gpt-image-2`，明确这一限制，按用户授权选择可核实路径。不可把工具显示名称当作后端证明。

当前技能编写时，环境内的imagegen说明列出了 `gpt-image-2`，并给出2048×1152和3840×2160尺寸。正式调用前核对实际工具能力；不要把这些文档示例伪装成内置工具专用参数。1920×1080是16:9，但某些API要求两边均为16的倍数，1080不满足，需采用支持的尺寸。

内置工具不可用时，按启动流程提供“配置API继续”与“跳过生图直接制作”的选择；有已授权全局API配置时按该流程实际测试并复用，不重复索取Key。只有用户明确选择或已有有效API授权时才使用CLI工作流，使用 `scripts/image_access.py` 加载全局凭据后直接调用原版CLI。不能调用不存在的工具，也不能用程序绘制的PPT截图冒充Image 2.0结果。跳过必须有用户明确选择并提示视觉效果和风格还原度可能下降。

## 从参考到风格校准

1. 按 `assets/reference-routing.json` 选择并打开技能内A/B对应参考图片。每次实际生成时，通过工具支持的图像输入/引用机制传入这些图片；在代理上下文看过、或在提示词写文件名，均不等于生成模型收到图片。
2. 选择参考角色：封面图控制封面结构，目录图控制导航版式，结尾图控制收束与首尾呼应，内容页参考控制标题和分区，方法页参考控制图文比例。项目报告必须分别为封面/目录/结尾提交同家族的A01/A02/A19或B01/B02/B28原图；正文风格校准不能代替这三类页。真实研究图作为“必须忠实保留的证据素材”单独标记。
3. 对含字母缩写、公式、真实截图的页面使用真实素材。图像模型不得改写截图里的字段、数据或印章；生成器不能忠实保留时，在图片阶段把原始素材准确合成到指定区域并如实记录合成方式。
4. 从最终所需页中优先做流程页和分点页；项目报告还校准封面，其他用途有封面需求时再做。与对应原始参考并排检查配色、页眉、图文比例、流程节点及分点层级，合格后完成其余页。所有校准页计入总数，不额外增加样稿。
5. 每页优先传1—2张内容结构相近的原始参考，加0—1张本套定稿样页。不要一次把47页缩略图全部当作主要参考，以免文字过小、风格目标相互干扰。定稿样页负责保持一致性，原始参考负责防止逐代偏离。

## 必须传达给生成器的风格摘要

结合当前页内容，把下列规则具体化后加入请求，不能仅留下“参考学术风格”一句：

- 内容：主题/问题在先，分组机制或证据居中，判断与对应证据靠近；允许中高信息密度，保留必要专业解释。
- 配色：白与极浅色承载内容，蓝色构建标题/模块/步骤层级，黑色完整说明，深红聚焦具体问题或关键判断；科研图内部数据色保留。
- 排版：明确蓝色页眉家族、细横线和可选左边标；主体采用所选原图的分栏/侧签/横条/主图侧栏结构，不把每页做成同一种网格。
- 流程：给出真实节点、分组、方向与边，明确先后、并列、包含、反馈；保持短标签和可辨认的连接边界。
- 分点：给出每点的短标签、核心定义和解释，使用蓝标签与浅底解释行/块等参考形式，保持同级对齐、组内紧凑、组间清楚。
- 证据：表格、科研图、截图、代码和公式都有明确角色及相邻说明，不以无关装饰替代；只用真实来源内容。
- 连续性：相同章节/模块沿用同一名称、颜色和总图；当前内容可用红框或主标题强弱定位，保持整套一致。

## 通用提示词母版

填入实际内容后保存为 `prompts/Sxx-v01.txt`。花括号是待填字段，不允许直接留在最终生成请求中。布局坐标是构图描述，不是模型保证精确遵守的约束，需要输出后核对。

```text
Use case: productivity-visual
Asset type: 一张完整的{已确认语言：中文/英文/其他}学术幻灯片图片，用于{论文讲解/组会/学术会议/项目汇报/答辩等本次用途}
Primary request: 生成第{页码}/{总页数}页，主题为“{本页标题}”。只输出一张完整幻灯片。
Input images:
  参考图1：本次已实际提交的原始PPT参考页，重点匹配其配色、标题位置、蓝色标签、浅色内容区及流程/分点组织，不复制原题目或单位。
  参考图2：同一套PPT已定稿样页，用于锁定视觉一致性。
  素材图3：真实证据，内容、标签、数据、比例须忠实保留。（有才保留该行）
Style/medium: 正式、克制、清晰的学术研究汇报，平面排版；按语言采用{风格锁中的中文黑体/清晰西文无衬线字体}，保持参考字重层级。
Language: {已确认文案语言}；所有上屏内容、节点、图注与目录均使用该语言，文献原题、作者、缩写、代码、公式按内容真源保留，不自动翻译或加入其他语言。
Canvas: 16:9，目标2048×1152，画面铺满，无外框、无屏幕或讲台场景。
Color palette: 白底#FFFFFF，主蓝#0B4FA1，模块蓝#004EA2，浅底#EAF2FF，正文#1C1C1C，少量强调红#C00000。
Typography: 内容页标题28—32pt视觉层级，正文18—22pt，图注较小但清晰。字体和字号感受与定稿样页一致。
Composition/framing: 优先接近参考图1的整体布局与信息密度。以1280×720逻辑画布描述位置，标题区x48,y28,w1184,h58，标题细线y100，主体区x48,y120,w1184,h532，可按参考具体调整。采用{本页页型与具体布局}。
Presentation grammar: {蓝标签+横向解释条/并列研究模块/分层流程/方法图+分点解释等}。明确每个分点的标签与说明，以及每个节点的连接关系。
Academic content: {本页要表达的研究关系，输入输出和因果含义}
Text (verbatim, 按区块逐字显示):
  标题：“{标题}”
  左区：“{准确文本}”
  右区：“{准确文本}”
  图注/来源：“{准确短引用}”
Emphasis: 仅把“{关键词或数值}”设为深红，其余正文黑色或深蓝。
Constraints: 只使用上列文本和提供的真实数据；保持术语、大小写、单位、上下标和节点关系；图和文字边界清楚，便于后续对象级重建。
Avoid: 透视、实物PPT投影照片、装订效果、霓虹光效、玻璃拟态、按钮式界面、多余卡通角色、伪校徽、伪引用、水印、无依据曲线、整段红字、文字乱码、四周留黑边。
```

用户指定原风格中某种装饰时保留，负面约束不能覆盖用户的新要求。每页只传递当前页所需的信息，避免把整篇论文塞进一个图像提示。

母版中的标题坐标和字号仅用于内容页。生成封面、目录、结尾时，用所选家族原图的构图替换 `Typography`、`Composition/framing` 和 `Presentation grammar`，不能让常规页眉覆盖大标题或蓝色宽带。

## 页级增量示例

### 封面

```text
采用A-cover，实际输入A01原页：上方小号“{本次学术汇报类型}”，中部白底深蓝高字重主副标题，两行以内。题目逐字为“{题目}”。下方只放本次需要的汇报人、单位和日期等真实信息，不默认加入指导教师。底部约1/4深蓝横带，可按本次信息量调整，放真实单位名称。无校徽素材时不生成校徽。
```

### 项目报告目录

```text
采用已锁定家族的目录，并实际输入A02或B02原页。章节文案逐字为{已确认的有序章节列表}，与正文分组一致。A式保留左侧约1/3蓝色竖栏和右侧编号横行，当前项蓝底白字；B式保留顶部蓝标题、编号方块加长横条，当前项红底白字。仅执行本套所选的一种，不混合两者。不添加没有正文的章节，不硬凑原图条目数。
```

### 项目报告结尾

```text
采用已锁定家族的结尾，并实际输入A19或B28原页及本套定稿封面。结束语逐字为“{用户已确认的结束语}”。A式延续白底深蓝大字和底部蓝色单位栏；B式延续浅灰几何底、蓝色宽带白字及横带下方留白。结束语为视觉主体，不插入密集结论、额外研究内容或参考中的人名单位。真实汇报信息仅使用{已知信息}。
```

### 研究现状与缺口

```text
采用Related-work：顶部“1.2 国内外研究现状”，主体为4—6行文献比较表。列名与逐行文本按提供内容，保持一行一篇或一类方法。浅蓝表头、白色表体、细蓝分隔。底部一句研究缺口，仅关键词深红。不要添加不存在的作者、年份、参考编号或性能数据。
```

### 技术路线

```text
采用Overview：以提供的节点和边列表绘制输入、关键模块、输出。主流程从左到右，反馈从下方返回，箭头关系严格按edge-list；模块内标签短而完整，节点间距足够。右侧保留约25%简述验证方法。所有节点使用平面清晰边界，不用3D设备图代替流程。关系列表：{完整节点和边}。
```

### 方法解释

```text
采用Method：左侧60%为{机制图}，右侧40%为{对应的分点解释}。蓝色模块标题，浅蓝底，正文左对齐。红色只强调“{一个研究差异}”。区分论文已证实结论、当前实验结果与待验证假设；仅在确为开题时使用计划或预期语气。
```

### 实验设计

```text
采用Experiment-plan：左侧数据集与实验条件表，右侧对照设置、评价指标、消融实验关系图。当前没有真实实验结果，不画虚构柱高或折线。使用任务和指标标签表达验证计划。若提供真实预实验数据，则逐点采用数据并明确“预实验”，不补造置信区间。
```

### 实验结果（仅有真实数据时）

```text
采用Results：左侧实验数值表，右上比较图，右下关键观察。数据逐字为{数据表}，横轴{类别/单位}，纵轴{指标/单位}。轴范围为{范围}，误差线仅使用提供值。最重要的方法用主蓝或红，其他浅蓝/灰，数值和图例一致。来源为{出处}。
```

## 修图与版本

按 `S09-v01`、`S09-v02` 保存修订记录，最终选择复制为 `images/S09.png`。一次修订聚焦一个问题，重复说明保持不变的配色、版式、其余文字及真实素材。

- 字误：明确“仅将A改为B”，逐字核对受影响区域，不能凭整体漂亮就接受。
- 重叠与连接错误：按 [逐页验收清单](quality-gates.md) 指出具体区域和节点ID，调整文字/图片边界、间距及箭头起终点，修图后逐页复查；未解决前不把该页当作定稿蓝图。节点间不要靠留出大缝隙隐藏悬空箭头，也不要用遮挡掩盖错误线段。
- 比例不符：优先重新生成正确比例；必要时等比例置于16:9画布或轻裁非内容边缘，记录处理，禁止拉伸文字和科研图。
- 数据图不准：回到源数据，修复原图或用真实图表合成到该页，保留“生成+证据合成”的记录。禁止为了视觉一致重造实验事实。
- 连续2次针对同一文字错误仍失败：优先调整布局或在生成图上局部排入已确认的准确栅格文字后重新检查；仍属于图片交付，但必须记录后处理。若需实质改写或删减已确认文案，先呈现改稿并取得确认。用户要求纯模型直出时说明限制，不悄悄后处理。

`generation-log.json` 逐页记录 `slide_id`、`tool`、`model`（不可见则`unexposed`）、`requested_size`、`actual_size`、`prompt_file`、`reference_files`、`references_actually_attached`、`reference_roles`、`style_comparison`、`selected_version`、`postprocess`。不能把代理看过的图片错误记为已传给模型。不储存API密钥。

最终图片应逐页提供，联系表只作为总览，不能替代全尺寸图片。`image-only` 到此结束，不插入PPT容器来冒充额外交付。
